## API and limits

`GET /api/v1/assets/export` uses the existing authenticated account and returns
`Cache-Control: no-store`. It exports the full account inventory, independently
of search/status filters and list pagination. No owner selector is accepted.

One bounded PostgreSQL statement reads the account's records and snapshot time.
Ordering is updated timestamp descending, then UUID descending. The query reads
at most 501 records to detect overflow. More than 500 records or a serialized
UTF-8 envelope exceeding 1 MiB returns 422 without producing a partial export.
Existing database timeouts apply; there is no automatic retry or file on server.

## Envelope

The outer object contains `format: "asset-desk-inventory"`, `schemaVersion: 1`,
`payload` (a JSON string), and lowercase hexadecimal `sha256`. Hash the exact
UTF-8 bytes of the payload string, not a parsed/reserialized object.

The payload contains UTC `exportedAt`, `complete: true`, `recordCount`, and
`records`. Each record contains only `id`, `name`, `category`, `serial`, `status`,
`notes`, `version`, `createdAt`, and `updatedAt`. Account IDs, credentials and
internal fields are excluded by explicit projection. Empty inventories are valid.

The checksum detects accidental changes; it proves neither authenticity nor
ownership. An export is sensitive plaintext inventory, not an encrypted backup
of accounts or the database. Do not upload it or paste real contents into chat.
No restore/import guarantee is made by schema version 1.

## Client acceptance requirements

- Request the dedicated export endpoint, never concatenate list pages.
- Validate envelope, checksum, record count, supported version and bounds.
- Require explicit preparation and local save; cancellation must not write.
- Clear prepared data on account/session change; reject late account responses.
- Preserve inventory/filter state on export errors and do not claim success.
- Check the actual rendered UI before and after implementation, including large
  text and keyboard access; test native save separately from synthetic renders.

## Parser reuse and evidence

The bounded duplicate-key/depth/Unicode JSON guard is adapted from ToolDeck
`apps/frontend/packages/flutter/lib/strict_catalog_json.dart`, specialized to the
1 MiB inventory envelope. Record validation reuses Asset Desk `AssetRecord`.
No external dependency was added. The parser requires an injected digest callback;
it must not be wired to a constant/test digest in production.

24 parser tests pass, including immutable complete records, unsupported versions,
count mismatch, duplicate IDs/keys, Unicode, oversized data and checksum failure.
Their digest callback is mocked: the synthetic fixture checksum is generated by
Python, and actual Windows BCrypt verification is recorded below. One initial test
exposed fixture text corruption through shell stdin; the fixture was regenerated
with explicit Unicode escapes and its checksum recomputed before the passing run.

The API client now requests only `assets/export`, uses the existing authenticated
session, and rechecks session revision after asynchronous digest verification.
63 combined transport/parser tests pass, including anonymous refusal, no retry,
401 invalidation, export-specific 422 messaging and sign-out during hashing.
Synthetic inventory baselines at 390/768/1440 pixels and 200% text were captured
before export UI edits; the 390-pixel render was inspected. These tests do not
use the product backend, PostgreSQL or an actual native hashing channel.

## Explicit Prepare/Save UI

Inventory exposes export only when the store supports the export capability.
Opening the page performs no request. Prepare fetches and validates the complete
snapshot; Save opens the Windows dialog. Cancel and save errors retain the
prepared snapshot. A new preparation clears stale data first. No automatic retry,
clipboard, record mutation or import is added. The account owner already replaces
the private navigator on session changes; disposed pages ignore late UI results.

Five export widget tests cover explicit actions, cancellation, save failure,
preparation failure, late completion and renders at 390/1440 pixels with 200% text.
Together with inventory regressions, 15 widget tests pass. The 390-pixel export
render was inspected; native dialog, keyboard and screen-reader acceptance are
separate checks, not proven by these synthetic tests.

Full offline Flutter verification now passes 133 tests. The first full run exposed
an Ahem-font lazy-list harness issue: Save was not yet built when `ensureVisible`
was called. The test now scrolls until the control is built; the suite passed
without changing product behavior. The synthetic captures use a local readable
font and are not native Windows acceptance.
